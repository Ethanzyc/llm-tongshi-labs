# prompt-engineering · 提示词工程实操

配套视频：《大模型通识04番外｜提示词工程实操》（父集：E04《提示词工程》）。

## 这个实验干什么

同一条任务（四条售后投诉自动质检），三版提示词，每版跑三遍，看输出漂不漂：

| 版本 | 内容 | 实测结果（2026-09-18，deepseek-chat） |
|---|---|---|
| V0 | 一句话「总结这些投诉」 | 诉求行时有时无、「三千多分」写成「3000多分」 |
| V1 | 五件套（角色/任务/背景/格式） | JSON 全稳，但优先级漂移 P0→P1→P0 |
| V2 | V1 + 两条标杆示例库 | 句式统一成标杆口径，情绪等级仍漂 高/中/高 |

**结论：格式和风格，提示词锁得住；判断类的东西锁不死，只能压小——残余漂移交给回归判分兜底。**

另有彩蛋对照组 `V1删格式`：删掉格式段模型仍自愈输出 JSON——惯性不是承诺，换个模型/换个任务这份运气随时用完。

## 文件

```
prompts/v0.txt v1.txt v2.txt   三版提示词全文（可直接抄）
complaints.txt                 四条测试投诉（第 4 条为多问题混杂边界题）
lab-run.mjs                    跑批：三版 × 各 3 遍 → results.json
check-regression.mjs           回归判分：类别/情绪等级/处理优先级 逐条一致性断言
results.json                   2026-09-18 真跑 11 次的原始输出留档（视频引用源）
```

## 复跑

```bash
export LLM_API_KEY=sk-xxx            # 必填
# 可选：LLM_BASE_URL（默认 https://api.deepseek.com）、LLM_MODEL（默认 deepseek-chat）
node lab-run.mjs                     # 约 11 次调用，几分钱
node check-regression.mjs            # 退出码 0=全 PASS，1=有红灯
```

改提示词就改 `prompts/*.txt`，重跑后对比 `results.json`——这正是视频里说的「改一版，跑一遍」。

## 口径

- 结果文件保留每次调用的原始输出，视频/文章引用数字与本仓库文件冲突时，**以仓库文件为准**。
- 采样为默认温度，不设 seed：实验目的就是观察自然漂移，不是复现单次输出。
